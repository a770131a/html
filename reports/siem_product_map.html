SIEM 產品功能地圖

這頁整理產品大項與下級項目：情資資料整理分三大類，第一類再拆兩種；第二類是外部產品 / AST / 正規化情資；第三類是紅藍隊情資。威脅判斷也分三大類：L5 加權判斷、UEBA、AI。

閱讀方式

先看資料責任，再看前台功能

這頁不是 Roadmap，也不是工時表。它是產品架構地圖，用「大項 -> 下級項目 -> 前台路徑」整理，避免資料來源、情資、威脅判斷、AI、訓練、前台功能混在一起。

前台路徑是目前建議 IA，可對應到已開 issue；實作時仍以 SIEM repo 內實際 router 命名為準。

核心邏輯：情資資料整理先分清三大來源；資料治理中心負責讓資料乾淨穩定；威脅判斷分成 L5 加權、UEBA、AI 三種；前台工作台只呈現 SOC 需要處理的狀態與下一步；訓練驗收負責證明 AI 和 L5 沒有越權。

情資資料整理：大項與下級項目

大項下級項目整理後進哪裡產品用途對應 issue
第一類：平台內生情資偵測 telemetry：Endpoint / Kernel / EDR / AV / SIEM / IDS / IPS。Canonical Event、Detection IR、L2 Signal、Evidence Pack。回答「主機、程序、檔案、網路、權限到底發生了什麼」。#24 #25 #26
第一類：平台內生情資治理 context：Asset / CMDB / identity / GCB / compliance / exposure / baseline。asset_context、entity_context、configuration_risk、context_multiplier。回答「這台設備、這個帳號、這個設定有多重要或多偏離」。#18 #19 #31
第二類：外部產品 / AST / 正規化情資外部產品告警：Defender、EDR、SIEM、IDS / IPS、AV、YARA、ClamAV。security_alert、malware_detection、external alert evidence。作為外部佐證，不能單獨越過 L5 或直接執行阻斷。#22 #34
第二類：外部產品 / AST / 正規化情資AST：SAST、SCA / SBOM、DAST / IAST / Runtime finding。vulnerability_context、exploitability、asset exposure、intel_context_score。把弱點變成風險上下文，不單獨宣稱 compromise。#28 #43
第二類：外部產品 / AST / 正規化情資CTI / IOC / KEV / EPSS / TTP mapping。intel_context_score、risk explanation、rule gap candidate。輔助優先級；IOC=0 不代表 living-off-the-land 低風險。#15 #28
第三類：紅藍隊情資紅隊攻擊劇本、藍隊偵測規則、紫隊對抗場景。scenario pack、golden fixtures、expected verdict、training seed candidate。用來驗證 detection、AI、L5 是否在邊界內做正確判斷。#1 #6 #14
第三類：紅藍隊情資Golden Replay、Windows_attack_v3、Structured Exams、human verdict。PMQA replay、audit snapshot、rule gap review、training seed review。用來閉環驗收，不讓 AI 只在風險分數上打轉。#8 #30 #36

第二類補充：外部產品 / AST / 正規化情資

SAST

原始碼弱點

靜態分析產生 weakness、sink/source、函式路徑、修補建議。進入 vulnerability_context，作為 asset 或 app 的風險背景。

SCA / SBOM

元件與供應鏈

整理 dependency、package、CVE、license、KEV、EPSS。用於 exploitability 與修補優先級。

DAST / IAST / Runtime

可利用與執行期證據

把掃描、runtime trace、web exploit attempt 與實際 asset exposure 合併。若沒有本機證據，不直接宣稱 compromise。

威脅判斷：三大項與下級項目

Judgement A

L5 加權判斷

下級項目：Hybrid Risk Weighting、gate threshold、approval_required、safe_auto_action、blocked disruptive action、scoring_breakdown。

回答「風險多急、要不要審批、哪些動作不能自動做」。對應 #28 #29 #34 #36

Judgement B

UEBA 判斷

下級項目：baseline deviation、entity graph、same user other hosts、same process pattern、cross-asset context、lab baseline。

回答「這個行為是否偏離平常、是否跨設備或跨身份擴散」。對應 #19 #32 #37

Judgement C

AI 判斷

下級項目：AI assessment、missing evidence、normal hypotheses、AI vs L5 comparison、rule gap candidate、human arbitration。

回答「AI 是否同意 L5、分歧在哪、下一步查什麼」。對應 #34 #35 #36

訓練與驗收有哪些

訓練 / 驗收測什麼用途對應 issue
COR ExamL2/L3/L4 關聯推理邊界。確認 AI 不把單點訊號誤判成完整 storyline。#9
RCA Exam根因分析推理邊界。確認 AI 能說明證據鏈，但不憑空補證據。#10
BND Exam邊界升級與不該升不升。確認 L5 / AI 分歧時能進人工複核或 rule gap。#11
ERM Exam風險治理與處置建議邊界。確認 guided response 不變成 unsafe auto response。#12
ROB Exam提示注入與使用者話術干擾防護。確認 AI 不被要求越權 approve / isolate / delete。#13
Golden Replay 100PoC / Shadow Mode 推理閉環。跑完整資料流、L5、AI、Comparison、Audit 的驗收。#14
Windows_attack_v3 E2E完整欄位 Detection IR fixture。驗證實際事件能支撐前台、Evidence Pack、L5 scoring。#30
