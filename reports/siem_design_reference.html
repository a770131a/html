核心原則

raw log 不可直接進攻擊主幹

所有來源資料都要先被 adapter 正規化，再進 Canonical Endpoint Event，之後由 mapper 轉成 Detection IR v1.1，通過 Schema Gate 才能進 L2/L3/L4/L5 分析。

分數不能繞過安全邊界。就算風險分數 90+，阻斷性動作仍需要人工審批。

資料流程總覽

1

資料來源

Agent / Kernel / Defender / ClamAV / SIEM / SAST / GCB / CTI / Asset context

2

Adapter

source-specific event 轉成 canonical；raw id、syscall、vendor fields 只保留 raw_ref/source_details。

3

Canonical Event

統一 actor、target、quality、raw_ref、evidence_refs。

4

Detection IR v1.1

只收 normalized behavior entities，通過 12 類 category 與條件式欄位驗證。

5

OpenSearch / Evidence Store

索引 normalized evidence、incident timeline、scoring breakdown；raw log 只短期或冷存。

6

Scoring / L5 Gate

#28 加權後輸出 observe / review / approve / escalate；阻斷性 response 永遠需要 approval。

專有名詞速查

這裡用產品與工程都看得懂的方式解釋名詞。原則是：資料層講來源與責任，決策層講安全邊界，前台只顯示分析師下一步需要知道的摘要。

名詞一句話解釋在流程裡的位置前台怎麼說
Raw Event來源系統送進來的原始事件，例如 syscall、EDR alert、AV scan log、vendor JSON。最前端來源資料，只保留 raw_ref / evidence_refs 供追溯。不要放在第一眼摘要；只在 Raw Event tab 顯示。
Canonical Event把不同來源資料整理成同一種事件格式，統一 actor、target、time、quality、raw_ref。Adapter 之後、Detection IR 之前。前台通常不直接顯示，只用它產出的主機、使用者、程序、目標。
正規化資料模型把不同來源的 log、alert、finding、context 轉成穩定欄位與 typed entity refs 的資料契約。Canonical Event、Detection IR、Evidence Pack、OpenSearch mirror 都要遵守。前台不顯示模型名，效果是同一台主機、同一個使用者、同一個程序能被穩定合併。
Detection IR v1.1偵測主幹的標準中介格式，只收 normalized behavior，不收雜亂 raw log。Canonical Event 通過 mapper 和 Schema Gate 後產生。顯示為事件類型、攻擊語意、L2/L3/L4 狀態。
AI DetectionAI 輔助判讀偵測語意、缺少證據、正常情境假說或 rule gap，不是直接取代 deterministic detection。Frozen AI Evidence Pack 之後，AI Assessment / Validator / Comparison 流程中。顯示「AI 輔助判讀」，不能說 AI 已覆蓋 L5 或已確認入侵。
UEBA Baseline使用者、主機、程序或帳號的正常行為基準，用來判斷是否偏離平常模式。Entity context / baseline store，作為 context_multiplier 或 baseline_deviation。顯示「相較平常行為偏高 / 輕微偏離 / baseline noise」，避免把所有偏離都說成攻擊。
Graph Correlation用 entity graph 把 host、user、process、file、network、IOC、asset 關聯起來。Correlation engine / Entity graph / Cross-asset context。顯示「同使用者、同程序鏈、同 IOC、跨設備相似 pattern」，不是顯示整張 graph。
Kill Chain Mapping把事件對應到攻擊階段，例如 execution、credential_access、persistence、command_and_control。Detection IR 後的語意標註，輔助 L3/L4 storyline 與 Attack Stage Distribution。顯示攻擊階段分布；未分類或 L2 單點訊號是正常狀態，不代表資料錯。
Case Grouping把同一主機、同一 correlation_key、同一攻擊鏈或同一調查目標的事件合併成 case。Incident / Case service，使用 dedupe_key、correlation_key、asset_id、storyline id。顯示「建立 Case / 加入既有 Case」，避免同一設備出現多張重複卡。
AI-assisted InvestigationAI 幫分析師整理證據、提出假說、指出缺少資料與下一步 hunt action。AI Assessment、AI vs L5、Investigation Drawer。顯示「建議先查 command line / network / persistence」，不是自動結案或自動處置。
Guided / Automated ResponseGuided 是引導人做下一步；Automated 只能做安全非破壞性動作，高風險阻斷仍需 approval。Response / Approval、L5 Safety Gate、Audit Trail。顯示「可建立工單、附加證據、收集 telemetry」；隔離、kill、block、delete 要顯示需人工審批。
Tailwind CSS前台 utility-first CSS 工具，用小型 class 快速組出一致的 spacing、顏色、排版、狀態樣式。Frontend UI layer；適合 Console、Drawer、KPI、Table、Badge、Tabs、Filter chips 等元件。前台不需要向使用者顯示 Tailwind，本質是讓 UI 更一致、可維護、快速迭代。
Investigation Evidence Pack調查證據包，補上 process tree、command line、network、file、user、timeline、cross-asset context。Detection IR / L5 之後，由 slow-path enrichment 產生。顯示在 Investigation / Evidence tab，回答「誰啟動了什麼、還缺什麼證據」。
Frozen AI Evidence Pack給 AI 的凍結版卷宗，從 Investigation Pack 摘要、去敏、截斷並加 hash。Stateful L5 Final Decision 之後，AI Assessment 之前。不直接顯示完整內容；前台顯示 AI 用了哪些證據與缺少哪些證據。
DB Source of Truth完整事實與稽核來源，保存 evidence、L5 decision、AI assessment、comparison、routing、audit。主資料層。前台不講 DB，只用它保證「這次判斷可追溯」。
OpenSearch Compact Mirror查詢與 timeline 鏡像，不是完整調查包，也不是 AI 直接資料來源。DB outbox 之後，用於列表、搜尋、聚合、PMQA replay。說成查詢層 / timeline / evidence index，不說成最終判斷來源。
L2 / L3 / L4L2 是單點訊號，L3 是多訊號候選鏈，L4 是已形成攻擊故事線。Detection IR 後的攻擊語意層。明確顯示「L2 only / L3 candidate / L4 storyline」，避免單點事件看起來像完整入侵。
L5 Safety GateServer 端安全邊界，決定 gate、審批、可安全自動動作、阻斷性動作封鎖。Risk scoring 後；Fast preliminary 與 Stateful final 都會產生 L5 decision。說「待確認高風險 / 需審批 / 自動處置已阻擋」，不說 AI 已確認入侵。
AI Reconciliation LayerAI 第二分析師與 Server L5 的比對層，一致提高信心，不一致進人工複核。AI Assessment 之後，Final Review Routing 之前。顯示「AI 是否同意 L5、分歧原因、下一步查證」。
Comparison Engine把 L5 gate 與 AI assessment 做一致 / 分歧 / rule gap / stale / unsafe action 判斷。AI Output Validator 之後。顯示 agreement_high_risk、disagreement_review、rule_gap_candidate 等狀態摘要。
Human Arbitration人類分析師或 SOC Lead 的最終仲裁，不讓 AI 覆蓋 L5 或直接處置。Final Review Routing 之後。顯示核准、拒絕、要求更多證據、標記誤報、加入備註。
tenant_id租戶 / 公司隔離 ID，例如 11111111，不是設備 ID。所有資料分區、查詢、dedupe、correlation 都會帶。預設不要顯示；主畫面顯示主機 / asset / agent，不顯示 11111111。
entity_refs標準化的 typed refs，例如 asset:xxx、agent:xxx、host:xxx、user:xxx、process:xxx。Detection IR、Evidence Pack、Correlation 使用。前台只顯示可讀名稱；raw refs 放進階區。
correlation_key / dedupe_keycorrelation_key 用來關聯同一組事件，dedupe_key 用來去重同類訊號。事件聚合、跨設備、timeline、避免重複卡片。主畫面不顯示；進階調查或 debug 才顯示。
safe_auto_action_allowed只代表可做非破壞性自動動作，例如 create_ticket、attach_evidence、collect_more_telemetry。L5 Safety Boundary。說「可建立工單 / 附加證據」，不能說可以自動隔離或 kill。
disruptive action會中斷服務或改變環境的動作，例如 isolate、kill、block、delete、disable。L5 hard boundary 與 Approval Queue。永遠顯示為需要人工審批，MVP 不自動執行。
scoring_breakdown風險分數拆解，例如 behavior_risk、intel_context_score、context_multiplier、confidence_multiplier。#28 Hybrid Risk Weighting Engine。用來解釋為什麼是這個分數；Risk Score 不等於攻擊機率。
partial_timeoutSlow-path enrichment 超時或部分資料缺失，例如 process tree 沒拿到。Enrichment Worker / Investigation Evidence Pack。顯示保守研判 banner，不因缺資料自動降級。
rule_gap_candidateAI 認為風險較高但 L5 較低時，建立規則缺口候選，不直接升級處置。L5 / AI Comparison。顯示為規則缺口審查，而不是立即判定入侵。

IR 怎麼整併

#26

Canonical Endpoint Event

所有 endpoint/source adapter 先統一成 canonical，保留共用欄位：tenant、asset、agent、timestamp、source、event_type、actor、target、quality、raw_ref。

{
  "schema_version": "deepxdr.canonical_endpoint_event.v1",
  "event_type": "process_exec",
  "actor": { "user": {}, "process": {}, "parent_process": {} },
  "target": { "file": {}, "network": {}, "system": {} },
  "quality": { "confidence": 0.8, "lossy_transform": false },
  "raw_ref": "raw:etw:uuid"
}
#25

Detection IR v1.1 Schema Gate

Canonical Event 由 mapper 轉入 Detection IR，通過 schema gate 才能進 `detection_ir_events`。heartbeat、inventory、usage summary、raw prompt content 不直接進攻擊主幹。

{
  "schema_version": "deepxdr.detection_ir.v1.1",
  "event_category": "process_activity",
  "event_type": "process_exec",
  "actor": {},
  "target": {},
  "context": {},
  "correlation": {},
  "evidence_refs": []
}

Detection IR 12 類主幹分類

process_activity、file_activity、network_activity、identity_activity、privilege_activity、persistence_activity、security_alert、malware_detection、data_activity、cloud_identity_activity、vulnerability_context、configuration_risk。

PASS_MAIN -> detection_ir_events PASS_CONTEXT -> context stores PASS_EVIDENCE_ONLY -> cold/raw store REJECT_QUARANTINE -> dead_letter_events

OpenSearch 放在哪裡

Storage / Search

OpenSearch 是查詢層，不是判斷主幹

Detection IR、Canonical Event、L2/L3/L4/L5 判斷仍由 schema、mapper、scoring engine 與 safety gate 控制。OpenSearch 負責索引、查詢、timeline、dashboard、PMQA replay evidence，不負責決定事件是否升級。

Source Event
  -> Adapter
  -> Canonical Endpoint Event
  -> Detection IR v1.1 Schema Gate
  -> normalized evidence index in OpenSearch
  -> Scoring / L2-L5 / Safety Gate
Data Governance

不要把 raw log volume 當產品價值

V41.1 的資料量治理原則仍適用：raw event 短期保存或冷存，normalized evidence 長期保存，dedup_hash 去重，entity_key 聚合，evidence pack snapshot 用於 PMQA/UAT。

OpenSearch 主要查 normalized IR 與 evidence pack，不應永久塞滿全量 ClamAV scan log、raw syscall、heartbeat、inventory dump。

Index / Store內容保存策略用途禁止事項
detection_ir_events通過 Schema Gate 的 normalized behavior eventshot/warm，依 severity 與 tenant policy事件查詢、L2-L5 分析、timelineraw log 不可直接寫入
canonical_eventsadapter 後的 canonical endpoint event短中期，支援 mapper/debug回查 adapter 轉換品質不可繞過 mapper 直接當 Detection IR
raw_event_store / cold storage原始 vendor log、syscall、scan raw output短 TTL 或 cold storage稽核、debug、raw_ref 回查不可當產品 dashboard 主資料
entity_context_snapshotsasset/user/vuln/intel/compliance context snapshot版本化保存risk multiplier、storyline context不可單獨確認 compromise
incident_timeline事件排序後的 evidence chain、scoring breakdown、decision trace長期保存SOC 調查、PMQA screenshot、客戶稽核不可缺 evidence_refs
pmqa_replay_reportsGolden replay、schema validation、safety gate test output長期保存驗收工時計算與 GA scorecard不可只有人工文字結論

#28 Hybrid Risk Weighting Engine 怎麼加權

Final Model

五維度 + 漏斗校準

1. 行為先定性
behavior_risk = static_behavior_base + actor_bonus + target_bonus + local_evidence_bonus + ttp_chain_bonus - benign_penalty

2. 情資再加權
intel_context_score = vuln*0.25 + ioc*0.25 + ttp*0.25 + ext*0.15 + gcb*0.10

3. 行為與情資整併
priority_base = behavior_risk*0.60 + intel_context_score*0.40

4. 上下文與信心校準
final_score = clamp(priority_base * context_multiplier * confidence_multiplier, 0, 100)

Scoring Breakdown

Detection IR 必須留下可解釋分解

{
  "risk_score": 82,
  "confidence": 0.86,
  "context": {
    "behavior_risk": 78,
    "vuln_score": 78,
    "ioc_score": 90,
    "ttp_score": 75,
    "ext_score": 65,
    "gcb_score": 40,
    "intel_context_score": 77,
    "priority_base": 77.6,
    "context_multiplier": 1.69,
    "confidence_multiplier": 0.951
  },
  "l5_gate": "escalate",
  "approval_required": true
}
階段設計查閱重點
Behavior basemalware=90、persistence=80、sensitive_file=75、process_exec_suspicious=60、normal=20先看行為本身，不先被 CVE/IOC 帶偏
IOC本機命中時按 confidence/freshness 加權；無本機事件時只給約 30% 權重避免只有情資清單命中就誤升級
TTP跨階段且 ttp_count >= 3 才給 chain_bonus單一 TTP 不等於完整攻擊鏈
Contextasset criticality、public exposure、baseline deviation 三類 multiplierpublic_facing 不可重複加權
Confidenceconfidence_multiplier = 0.65 + 0.35 * confidence低信心不能把高風險 malware 壓成低風險
Overrideforce escalate / force approve / downgrade / suppress硬邊界優先於公式

L5 Safety Gate 與自動化邊界

Gate Thresholds
scoregate行為
0-39observe寫入 IR，不通知 SOC
40-64review建立 Incident，L5 只給建議
65-79approveresponse action 需 SOC Lead 核准

Hard Boundary

不可自動執行阻斷性動作

允許自動：create_ticket、notify_soc、send_slack、send_email、attach_evidence、increase_case_priority、open_case_note。

永遠需要人工審批：isolate_host、kill_process、block_ip、disable_user、revoke_token、delete_file、quarantine_asset、cross_tenant_action。
