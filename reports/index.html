二、最大缺口：Workflow Layer

Task Center

P0

把 Agent 離線、弱點、GCB/VANS、授權浪費、AI policy violation、XDR incident 都轉成可指派、可追蹤、可驗收的任務。

Approval Center

P0

高風險 response、AI 上傳例外、GCB 例外、弱點延後修復、軟體安裝例外都需要一致的審批流程。

Evidence Center

P0

合規與稽核商品化核心：控制項、證據、缺口、改善、驗收、報表都要能追溯。

Role Scope Engine

P0

不能只靠 role，還要支援部門、資產群組、欄位遮罩、audit period、action scope。

Incident Workflow

P0

XDR 需要 new、triaging、investigating、response_pending、contained、resolved、false_positive、closed。

Report Center

P1

主管、稽核、財務、部門各需要不同報表；同一份資料用不同 scope 與遮罩呈現。

四、建議實作順序

Phase 1
ITAM 作業閉環

資產 → Agent → 軟體 → 弱點 → GCB/VANS → Task Center。

Phase 2
XDR 作業閉環

L2/L3/L4 → Incident Workflow → SOC Analyst → Response Approval。

Phase 3
合規作業閉環

Control → Evidence → Gap → Remediation Task → Audit Report。

Phase 4
AI 治理閉環

AI Policy → Data Risk → Block/Allow → Exception → ISO 42001 Evidence。

Phase 5
HR / Finance / Department 角色視角
